# 100K 星火奖 · Three.js 开发接入说明

版本：`100k-en-badge-zh-ui-2026-09-24`。

本包为最新 **100k 英文徽章＋中文 UI**。开发将模型、开屏和交互接入自己的页面；随包页面是效果参考及可运行源码，不要求整站替换。本次没有发布到线上，也不包含 50k、Figma 文件或完整交互录屏。

## 1. 本版确认范围

- 徽章使用 `Spark_Award_100K_EN.glb` 的原始字节，项目内沿用资源名 `Spark_Award.glb`。
- 背面文字为 **Your Models Have Been Printed / 100,000 Times / MakerWorld**。
- 正面字形、Body / Star / Recess 几何、材质和渐变贴图与之前版本核对一致。
- UI 保留中文：星火奖、您的模型累计被打印 100,000 次!、恭喜获得「星火奖」、获得日期、分享、确认。
- 保留原有开屏视频、揭晓时间轴、旋转与回正、流星、光尘、微弱背光和侧面反光抑制。
- 仅以本包预览和素材作为本版对照；旧链接、旧包可能仍是之前的背面。

## 3. 先查看效果

直接打开 `preview/星火奖预览.html` 可对照效果。需要调源码时，在交付包根目录执行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory threejs
```

- 正式效果：`http://127.0.0.1:8765/`
- 材质调试：`http://127.0.0.1:8765/badge-lab.html`
- 时间轴调试：`http://127.0.0.1:8765/?debug=1`，面板仅在本地开启。

源码页依赖模块及资源请求，应通过 HTTP/HTTPS 访问。Three.js r180 与 GSAP 3.13.0 已在 `vendor/` 中，无需 npm 构建或外部 CDN。若使用宿主工程依赖，请确保 Three.js 核心和 addons 版本一致。

## 4. 接入开发自己的弹窗

### 模块入口

| 文件 | 接入职责 |
| --- | --- |
| `BadgeGLB.js` | 加载 GLB、显示尺寸归一化、应用主题及模型资源释放 |
| `BadgeThemes.js` / `BadgeThemeConfig.js` | 四区域材质、四颜色主题及配置 |
| `BadgeGLBEnvironment.js` | HDRI → PMREM，ACES / AgX 校色 |
| `BadgeUnlockSequence.js` / `BadgeUnlockConfig.js` | 开屏到奖牌揭晓的状态机、时间轴和屏幕适配 |
| `BadgeOpeningVideo.js` | 视频首帧、循环、暂停、失败回退及清理 |
| `BadgeUnlockEffects.js` / `BadgeBackdropEffects.js` | 揭晓特效，以及流星、光尘与背部微光 |
| `BadgeStudio.js` | 保留现有环境与辅助光照 |
| `app.js` | 完整接线示例：相机、灯光、后处理、唯一渲染循环、拖动与旋转 |
| `index.html` / `style.css` / `ui.js` | 中文弹窗结构和状态参考，不是必须替换的宿主 UI |

建议以 `app.js` 为接线参考，将模型、时间轴及特效纳入宿主弹窗。当前是一套可运行模块源码，**尚不是带 `mount(container)` 的框架组件或多实例 SDK**，不能直接把 `app.js` 导入任意弹窗便假定完成接入。

当前 `BadgeUnlockSequence` 会查询 `.award-screen`、`.award-copy`、`.award-actions`、`.controls` 等 DOM，依赖 `#award-title`、`.award-message`、`.award-date`、`#share-award`、`#confirm-award`、`#action-status`；`app.js` 还使用 `#scene`、`#rotate`、`#reset`。`ui.js` 使用 `#award-date`。可保留参考结构，也可将这些查询改成宿主传入的元素引用。使用后者时应保留原有状态、时间轴和禁用 / 恢复交互逻辑。

接入顺序：

1. 创建弹窗容器和 Canvas，设置相机、renderer、后处理，并准备 UI 元素。
2. 加载本地 GSAP（当前模块读取 `window.gsap`）、GLB 和 HDRI，套用当前主题配置。
3. 模型加载成功后再创建 `BadgeUnlockSequence`，参考 `app.js` 传入 scene、camera、renderer、composer、bloom、badge、atmosphere 和回调。
4. 用同一个渲染循环更新动画、模型和特效；准备完成才允许触发揭晓。
5. 将原有拖动、自动旋转和回正绑定到宿主对应控件；保持加载中、播放中和可交互三种状态。
6. 弹窗关闭 / 组件卸载时停止渲染循环、取消事件监听和 ResizeObserver，释放 sequence、模型、HDRI、后处理与宿主拥有的 renderer。页面隐藏时暂停，恢复时重置时间差。

`badgePresentation.close()` 仅关闭开屏模块，**不代表整个 renderer 和弹窗都已销毁**。当前示例在页面离开时另做清理；在 SPA 中需要将这部分迁移到组件卸载生命周期。当前使用全局 DOM 和共享配置，不支持同页同时挂载多个奖牌实例；若产品需要多实例，应先隔离容器查询、状态和配置。

资源路径默认相对于页面地址。放入子目录 / 构建工具后，需统一调整模型、HDRI、视频、SVG 和模块路径。跨域素材需要 CORS；如有 CSP，应适配 import map 和脚本加载。不要混用新旧缓存的 GLB 和配置。

### 现有参考页 API

在资源初始化完成、WebGL 加载成功后：

```js
window.badgePresentation.setTheme('silver'); // silver / gold / blue / black
window.badgePresentation.getTheme();
window.badgePresentation.reset();           // 停止自动旋转并回正
window.playBadgeUnlock();                   // 重播；播放中重复触发会被忽略
```

这些是参考页暴露的接口；仅导入 `BadgeGLB.js` 不会自动创建它们。将宿主需要的入口封装到其组件实例上即可。模型自身的 `load()`、`setTheme()`、`setSettings()`、`setEnvironment()`、`dispose()` 可在对应生命周期调用。

## 5. 动画、材质与 UI 基准

正常揭晓约 2.65 秒：0 秒收缩，0.28 秒穿梭，0.72 秒星芒，1.05 秒闪光，1.16 秒出现 GLB，1.70 秒上移，1.98 秒出现 UI，2.48 秒开放交互。减少动态模式约 0.65 秒，不使用穿梭 / 白闪，默认不自动旋转。

开屏 MP4 约 4.04 秒、720×720、24fps、静音循环。绿幕已处理并合成黑底，参考页用 `mix-blend-mode: screen` 融合；**不是带 Alpha 的透明视频**。保留深色背景及对应融合方式。视频加载失败 / 超时回退到程序化晶体。

当前银色默认 ACES、曝光 0.91，输出 sRGB。HDRI 作用于模型，特效材质单独管理。不要用统一材质覆盖模型所有表面；需要保留凹槽、星形、文字、边缘之间的差异，以及对 Body_Edge 低反射 / 低亮度的额外处理。

| Silver 区域 | color | roughness | metalness | envMapIntensity |
| --- | --- | --- | --- | --- |
| Body | #ffffff | 0.270 | 1 | 1.00 |
| Star | #ffffff | 0.225 | 1 | 0.90 |
| Text | #ffffff | 0.205 | 1 | 1.00 |
| Recess | #eeeeee | 0.430 | 1 | 0.78 |

颜色为叠乘到原始 GLB 基色 / 渐变上的 sRGB 色调。另有 Gold / Blue / Black 配置；它们是本模型已有的换色能力，不代表其他等级已完成交付。完整参数以 `BadgeThemeConfig.js` 为准。厚度、倒角与字形来自模型，不用网页参数重新生成。

流星每 3 秒依次走三条上方路径，单次约 0.48 秒；靠近奖牌的光尘桌面 14 颗、移动端 9 颗，另有独立细背景星尘；背部微光透明度 0.048。保留防遮挡处理，特效对象不复用奖牌材质。

调试页“应用到正式页”只保存到同源浏览器的 `spark-award:glb-themes:v1`。给所有用户发布参数，需要导出并替换配置文件；验收默认银色时可“恢复默认”再应用，避免本地旧调试值覆盖。后续等级应分别配置模型资源和存储命名空间，不覆盖本版基准。

中文 UI 是当前确认版本。未来英文 UI 文案应在宿主的国际化层管理，不需要更换这份英文 GLB。参考页日期为访问者本地今日日期，跨午夜 / 回到前台会刷新，并非真实服务端获奖时间。

分享目前生成 1080×1440 PNG，优先系统图片分享，降级为下载或文字分享；实际产品分享渠道由开发接入。确认目前回正奖牌、清理开屏并显示“已确认”，不执行后端发奖、关闭业务弹窗或跳转。100k 达成判断、领取记录和展示频次同样由产品系统接入。`badgeawarded` 是前端动画触发事件，不是服务端授奖凭据。

`badge-svg-lab.html` 与 `Badge3D.js` 是保留的旧 SVG 工作流，不参与本版正式模型加载；请使用英文 GLB，勿从旧 SVG 背面重建当前奖牌。

## 6. 检查与交付边界

模型替换阶段已用真实 GLTFLoader 进行 CPU 集成检查：9 个材质批次、3 张内嵌贴图、归一化尺寸、80 次主题切换、独立特效材质、HDRI 解析、重载与释放通过。原始材质 / 贴图、主体 / 星形 / 凹槽几何，以及正面 133,404 个文字三角形核对一致；替换时其余 50 个运行文件未改。

本次打包核对 JavaScript 语法、模块及页面资源引用、源码复制一致性、GLB 与所提供英文原件一致性、自包含预览的可重复构建，以及 ZIP / 文件哈希完整性。上述检查不等同于 GPU 视觉验收。

开发在目标浏览器 / WebView 上需要验收：正反面文字与反光、首帧加载、过渡时间、按钮状态、拖动旋转、分享 / 确认、横竖屏、减少动态模式，以及关闭 / 重进后的资源释放和实体手机帧率。当前最新版未完成自动化浏览器 GPU 与实体手机验收。

修改源码后，在包根目录执行 `python3 tools/build-preview.py` 可重建预览及源码 ZIP。`文件校验.json` 是本次交付快照，修改文件后需另行更新。后续等级以独立版本交付，不覆盖此包。
